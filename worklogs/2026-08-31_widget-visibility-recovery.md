# 2026-08-31 위젯 상시 표시 복구

## 관찰된 증상

- Daybridge 프로세스와 로컬 일정 브리지는 살아 있지만, 투명 오버레이가 Windows 화면에서 사라질 수 있었다.
- 런타임 기록에는 오버레이 닫힘이 아니라 대시보드 닫힘만 남아 있었고, 저장 좌표도 현재 작업 영역 안에 있었다.
- 강제 숨김 검증에서 기존 Tauri `show()` 호출은 복구 기록을 남겨도 Windows의 실제 visible 상태를 되살리지 못하는 경우가 확인됐다.

## 구현

- 앱 본체에 3초 주기의 오버레이 감시를 추가했다. WebView 타이머와 무관하게 표시·최소화·최상단 상태를 재확인한다.
- Windows에서는 `ShowWindow(SW_SHOWNOACTIVATE)`와 `SetWindowPos(HWND_TOPMOST)`를 함께 호출한다. 키보드 포커스를 빼앗지 않으면서 OS 수준의 표시와 최상단 순서를 복구한다.
- 모니터, DPI, 작업 표시줄 변경으로 창이 화면 밖으로 완전히 벗어난 경우 현재 모니터 작업 영역의 오른쪽 아래로 복구한다. 사용자가 의도적으로 화면 중앙에 둔 위치는 유지한다.
- 실제 복구에는 이전 표시·최소화 상태, 복구를 요청한 경로, 화면 밖 좌표 복구 여부를 런타임 NDJSON에 남긴다. 감시 오류는 첫 오류와 반복 오류만 기록한다.

## 검증

- Rust 단위 테스트 2건: 정상 작업 영역 유지와 모니터 변경 뒤 화면 밖 좌표 감지를 확인했다.
- 타입 검사, 퀘스트 컴파일러 테스트 8건, 데스크톱 창 위치 테스트 2건, Playwright 위젯 회귀 검사를 통과했다.
- 패키지 위젯을 다시 빌드·재기동한 뒤 Windows 창을 테스트에서 숨겼고, 실제 `visible=true` 복구와 `native_watchdog` 복구 로그를 확인했다.

## 운영 확인 방법

- 재발 시 트레이 메뉴의 **위젯 다시 표시**를 사용한다.
- 런타임 기록에서 `overlay_visibility_recovered`의 `source`, `previouslyVisible`, `previouslyMinimized`, `repositionedFromOffScreen`을 확인한다.
