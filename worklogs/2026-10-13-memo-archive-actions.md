# 메모 보관함 조작 개선: 2026-10-13

사용자 요청: 맨 위까지 드래그 가능, 각 목록 행의 휴지통, 삭제 후 다음 메모 자동 선택, 크고 구분되는 하단 액션.

상단24px(좁은 창16px) 패딩은 기존 header drag 영역 밖이었다. 이 여백에 명시적인 드래그 면을 두고 제목/여백 mousedown을 native startDragging에 연결했다. 버튼은 드래그에서 제외하며 기존 archive 창의 allow-start-dragging 권한을 사용한다.

목록의 선택 버튼과 삭제 버튼을 형제 요소로 구성해 중첩 버튼과 클릭 전파를 피했다. 삭제 성공 후 다음 항목, 끝이면 이전 항목, 모두 없으면 빈 상태로 바뀐다. 다른 항목을 삭제해도 삭제한 행의 이웃을 선택한다. 다음 본문을 읽을 때까지 busy를 유지하고 늦은 read가 새 선택을 덮지 못한다. 더 보기 이후의 삭제도 원래 이웃을 찾을 때까지 페이지를 갱신한다. 실패/부분 저장은 메모를 제거하거나 이동시키지 않는다. 삭제 후 목록 키보드 초점도 다음 선택으로 이동한다.

하단은48px 높이·14px 글자·20px 아이콘·12px 모서리로 확대했다. 저장은 녹색, 일정은 보조 면/테두리, 삭제는 분리된 버튼이다. 좁은 본문에서는 두 주요 액션과 삭제를 두 줄로 배치한다. 기존 저장/일정/native 데이터 계약과 재시작 실행본 보호는 유지했다.

타입 검사·관련 메모27개 통과. 격리 브라우저8조건과 삭제 전용720/420px2조건에서 자동 선택·이전 선택·마지막 빈 상태·삭제 실패 보존·초점·48px 액션·상단 hit coverage·일정 공존·저장 및 모션 감소를 확인했고 페이지 오류0이다. 720/420px 실제 렌더링 캡처를 검토했다. 브라우저의 상단 hit 검사는 OS 창 이동 자체의 실증이 아니다. 운영 패키지/설치 및 실제 native 드래그는 별도 근거로 확인한다.
